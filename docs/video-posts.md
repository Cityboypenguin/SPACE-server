# 動画の投稿

投稿・返信・メッセージ（DM・コミュニティ・授業内チャット）に動画を1本付けられる。
質問・回答には付けられない。大学の Azure Blob Storage の容量・通信量と、1 vCPU の API
サーバーの負荷を抑えることを優先した作りになっている。

## 仕様

| 項目 | 値 | どこで守るか |
|---|---|---|
| 容器・映像・音声 | MP4・H.264・AAC（音声なしも可） | 端末で変換、サーバーで中身を検査 |
| 解像度 | 横 1280×720 / 縦 720×1280 以内（拡大しない） | 同上 |
| 長さ | 60秒以内（サーバーは音声の先頭の無音ぶん 0.1 秒の幅を持つ） | 同上 |
| フレームレート | 30fps 以内（30 を超えるときだけ 30 にする） | 同上 |
| 容量 | 圧縮後 25,000,000 バイト以内 | 端末で再圧縮（最大3回）、サーバーで実物を測る |
| 圧縮前の容量 | 300MB 以内、元の解像度は 4K（4096×2160）以内 | 端末 |
| 1件に付けられる数 | 動画1本。画像・スタンプとは同時に付けない | サーバー |
| 編集 | 動画を外すことだけできる（後から足せない） | サーバー |
| 保存期間 | 初期値 90 日（`system_settings.video_retention_days`） | アプリと Azure の2段 |

## 流れ

```
端末  選ぶ → 事前チェック → Worker で圧縮（WebCodecs / Mediabunny）→ サムネイル → プレビュー
      投稿 → presignedVideoUploadUrl / presignedVideoThumbnailUploadUrl
           → staging/videos/… と staging/video-thumbnails/… へ PUT（XHR で進み具合を表示・中止可）
           → createPost / sendMessage（videoInput）
API   上限の確認 → AcceptVideo（実物を測る → 先頭 1MB を読んで InspectMP4 → 最終キーへコピー）
      → サムネイルを受け入れ（既存の画像の検査）→ DB に保存（失敗したら両方のファイルを消す）
再生  再生ボタン → requestVideoPlayback → 期限付きの読み取り SAS → <video src>
期限  読み出しのたびに「登録時刻 + 現在の保存期間」で判定 → 日次の処理（04:00 JST）で実体を削除
```

## 受け入れ（internal/upload）

既存の受け入れ（`docs/user-content-serving.md`）にそのまま乗せてある。署名付きURLが
書けるのは `staging/` だけで、受け入れのたびに引き直した最終キーへサーバー内でコピーする
（検査後の差し替えを防ぐ）。動画で足したのは次の2点。

- **`InspectMP4`**（`internal/upload/mp4.go`）。先頭 1MB に収まる moov を自前で読み、
  コンテナー・コーデック・長さ・解像度・fps・表の整合（全サンプルが mdat の範囲内か）を
  確かめる。拡張子・Content-Type・クライアントの申告は判断に使わない。
- **デコードはしない**。1 vCPU のサーバーで投稿のたびに数秒ぶんの CPU を使わないため。
  そのため、表は正しくサンプルの中身だけが壊れたファイルは通る（見た人の画面で
  再生できないだけで、害は広がらない）。サムネイルが本当にその動画の1コマかも確かめない。

moov を先頭に置くこと（faststart）を必須にしている。端末の圧縮は必ずそう書き出すので、
正しく作られた投稿は落ちない。末尾にあるもの・断片化したものは断る。

## 置き場と配信

- 動画とサムネイルは専用のコンテナー **`space-videos`**（`VIDEO_CONTAINER`）に入れる。
  **匿名読み取りを許さない。** 公開のコンテナーに入れると、保存期間が過ぎた後も URL を
  知っている人は実体が消えるまで見られる。
- 表示は期限付きの読み取り SAS だけで配る。再生用は「1時間」と「保存期間の期限」の早い方、
  サムネイルは1時間の窓で丸めた期限（同じく保存期間の期限を越えない）。期限が過ぎたら、
  実体がまだ残っていても新しい URL は出ず、出した URL も期限で切れる。
- Range リクエスト（シーク）は Blob がもともと対応している。`Content-Disposition: attachment`
  は付いたままで、`<video>` の再生には影響しない。
- 動画は `Post.media` には入れず `Post.video` / `Message.video` として返す。動画を知らない
  古いクライアントに渡さない（`<img>` で描こうとしない）ため。

## 保存期間

- 値は `system_settings` にだけ持つ（マイグレーション 133 が 90 を入れる）。コードには書かない。
  行が欠けていたら動画の投稿・再生・削除をすべて止める（既定値で消していかない）。
- 期限は列に持たず、`media.created_at`（動画の登録＝投稿成立）と現在の設定から毎回計算する。
  保存期間を変えると、まだ消していない既存の動画にもそのまま効く。
- 管理画面（`/admin/videos`）で変えるときは、先に影響（すぐ見えなくなる本数と容量、
  7日以内に期限が来る本数）を表示し、確認した本数と変更時の本数が違えば変更しない。
- 期限が来たらすぐ再生できなくなり、**猶予**（`video_purge_grace_days`、初期値 3 日）の後に
  日次の処理が実体を消す。猶予は、保存期間を誤って短くしたときに戻せるようにするため。
  1回に消す本数は `video_purge_batch_size`（初期値 200）で抑える。
- 消せなかった動画は `video_assets.purge_*` に記録し、1時間後にやり直す。
- 投稿者が外した動画、管理者が外した動画、削除された投稿・メッセージの動画も、猶予の後に消す。
- **未対応・確認中の通報が付いている投稿・メッセージの動画は消さない**（通報への対応が終わるまで）。

### 通報と動画

- メッセージの通報の写し（`ReportedContent`）には、動画のキーと実測値を入れる（`ReportedContent.video`）。
  画像と違ってファイルは写し取らない（大きく、保存期間の決まりもあるため）。
- 管理者は通報の詳細から再生できる（`adminRequestReportedVideoPlayback(reportID)`）。
  チャット詳細（コミュニティ・授業・DM の管理画面）にも動画を出し、そこから外せる。
- **退会**: 退会で media の行は消えるが、未対応・確認中の通報が付いたメッセージの動画は
  ファイルを消さずに `reported_video_retentions` に記録し、通報の詳細から再生できるようにする。
- **対応が終わったら**（解決・却下）:
  - 退会で残した動画は、次の日次の処理（04:00 JST）で消す。
  - それ以外は通常の決まりに戻る（期限・外した・投稿の削除から猶予の後に消える）。
    例えば対応として投稿を消せば、猶予（初期値3日）の後に消える。
- 投稿の通報には写しが無い（既存の設計）ので、投稿者が退会すると投稿の動画は他の添付と同じく消える。

### 期限後の表示

本文・コメント・いいね・投稿者・日時はそのまま残り、動画の位置に
「動画の保存期間（90日間）が終了しました。」と出す（日数は設定に従う）。通信の失敗は
「動画を読み込めませんでした」と再試行のボタンで、期限切れとは別に出す。

## Azure Blob Storage の設定（2026-11-20 適用済み）

以下を実環境に適用した。適用後、アプリのコードで「staging への PUT → 受け入れ（検査）→
署名付きURLで Range の読み取り（206）→ 匿名の読み取りは拒否」を確かめ、確認用のファイルは消した。

1. コンテナー `space-videos` を作った（匿名アクセスなし）。

   ```sh
   az storage container create --account-name 20261024project202609su \
     --name space-videos --public-access off --auth-mode login
   ```

   本番 VM のマネージド ID はストレージアカウント単位で「ストレージ BLOB データ共同作成者」を
   持っているので、このコンテナーにも追加の割り当ては要らない（確認済み）。
   CORS はアカウント単位で、既存の PUT の設定（`Content-Type`・`x-ms-blob-type`）がそのまま効く。

2. ライフサイクル管理の規則を足した（既存の `delete-old-db-backups` は残してある）。

   ```json
   { "rules": [
     { "name": "video-staging-cleanup", "enabled": true, "type": "Lifecycle",
       "definition": {
         "filters": { "blobTypes": ["blockBlob"], "prefixMatch": ["space-videos/staging/"] },
         "actions": { "baseBlob": { "delete": { "daysAfterCreationGreaterThan": 1 } } } } },
     { "name": "video-backstop", "enabled": true, "type": "Lifecycle",
       "definition": {
         "filters": { "blobTypes": ["blockBlob"],
                      "prefixMatch": ["space-videos/videos/", "space-videos/video-thumbnails/"] },
         "actions": {
           "baseBlob": { "delete": { "daysAfterCreationGreaterThan": 120 } },
           "snapshot": { "delete": { "daysAfterCreationGreaterThan": 1 } } } } }
   ] }
   ```

   - 1つめは、アップロードしたまま投稿されなかった動画（staging）を1日で消す。
   - `version` の削除は入れていない（バージョニングが無効のため。有効にするなら足す）。
   - 2つめは**安全網**。アプリの日次の処理が止まっていても、作られてから 120 日で消える。
     保存期間を変えられるので、アプリより先に消さないよう「保存期間の上限より長く」してある。
     アプリには同じ日数を `VIDEO_LIFECYCLE_BACKSTOP_DAYS` で渡し、管理画面で設定できる
     保存期間は「この日数 − 猶予 − 7日」まで（初期値なら 110 日）に制限する。
   - 対象はコンテナー名を含むプレフィックスだけなので、画像・アバター・DM の添付には効かない。
   - Azure のライフサイクル管理は1日1回程度で、時刻は厳密ではない。期限後の再生はアプリ側で
     止めているので、ここが遅れても見えることはない。

3. 論理削除・バージョニング

   - Blob の論理削除は **30 日間有効**（2026-11-20 確認）。アカウント単位の設定で、
     コンテナーごとには変えられない。アプリが消した動画も 30 日間は論理削除の状態で残り
     （利用者からは見えない。復元できるのはストレージの権限を持つ人だけ）、容量に数えられる。
     保存期間 90 日 + 猶予 3 日 + 30 日で、最長およそ 123 日ぶんの容量を使う。
   - Azure の「完全削除」（`deletetype=permanent`）は論理削除されたスナップショット・バージョンにしか
     使えず、通常の Blob を論理削除を飛ばして消す手段は無い。短くするには、論理削除の日数を
     アカウントごと縮めるか、動画だけ論理削除の無い別のストレージアカウントに置くかになる
     （どちらにするかは未決）。
   - バージョニングは無効、コンテナーの論理削除は 30 日（2026-11-20 確認）。確認のコマンド:

     ```sh
     az storage account blob-service-properties show \
       --account-name 20261024project202609su \
       --query "{softDelete:deleteRetentionPolicy, versioning:isVersioningEnabled, containerSoftDelete:containerDeleteRetentionPolicy}"
     ```

## 量の把握

管理画面の「動画」に、保存中の本数と容量、今日・今月の投稿数とアップロード容量、
検査で断った件数、自動削除の件数と失敗、日ごとの集計を出す（`video_daily_stats`）。

ダウンロード量は「再生用 URL を出した回数 × 動画の大きさ」の**上限の目安**しか出せない
（途中で止めた・シークした・キャッシュから出た分を区別できない）。実際の転送量は
Azure Monitor のストレージアカウントの「Egress」で見る（コンテナー単位では出ない）。

上限（1人1日の本数・容量、全体の容量）は `system_settings` にあり、初期値はすべて 0（無制限）。
値は利用状況と予算を見て決める。別に、署名付きURLの発行は1人1時間20回まで（Redis）。

## 未対応・今後

- 投稿の通報には写しが無いので、通報中の投稿でも投稿者が退会すると動画は消える（画像と同じ）。
- Azure の安全網（120 日）は通報中でも消す。作られてから 120 日を超えて対応が続く通報では、
  動画が先に消える。
- HLS・複数画質の配信はしない（単一の MP4）。
